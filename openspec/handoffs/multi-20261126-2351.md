### Change 3: `project-persistence`

- **Change Directory**: `openspec/changes/project-persistence`
- **Architecture & Technical Boundaries**:
  - IndexedDB `rgb-pencil` v1 with stores `projects` (key `id`; indexes `updatedAt`, `sourceHash`), `images` (key `projectId`: `{ png: Blob, thumb: Blob, width, height }`), `meta` (`lastOpenedProjectId`). Thin local promise helper; no `idb`.
  - **Lossless PNG** for the working bitmap (never JPEG): restore must be byte-exact so `sourceHash` is unchanged. The original photo is never stored.
  - Project id = `crypto.randomUUID()`; `sourceHash` only for same-image detection and legacy migration.
  - Completed cells as a bitset (`ceil(cols × rows / 8)` bytes, bit `row * cols + col`), converted from/to the runtime `Set<string>` at the storage boundary only; out-of-range bits ignored on decode.
  - Autosave: debounce `500` ms, immediate flush on `visibilitychange` (hidden) and `pagehide`, serialised writes, status `saving | saved | error | memory-only`; `navigator.storage.persist()` called once after the first success; memory-only mode and `QuotaExceededError` handled without throwing.
  - Resume last-opened project before first grid render; sample scene only when no project exists. `schemaVersion` guard: a newer record is refused and never modified. `pipelineVersion` mismatch shows a notice only.
  - Geometry lock enforced **in store actions**: width/palette locked while `doneCount > 0`; contrast/dither require `confirmed: true` while cells are done; declined changes issue no pipeline request. "Start new drawing from this image" creates a sibling project.
  - Backup file `.rgbpencil.json` (`format: "rgb-pencil-project"`, `version: 1`); import validates size (`<= 8 MB` before parsing), JSON, structure, ranges (`cols 16–96`, `rows 1–512`, contrast `1.0–2.3`, ditherStrength `0–1`, known palette), bitset length, PNG decode, bitmap `<= 1024 px`; always creates a **new id** and never overwrites; names rendered as text only. Backup nudge once at `50` completed cells without export.
  - Multi-tab: Web Lock `rgb-pencil:project:<id>` with `ifAvailable`; read-only mode with banner; `Take over` via `steal` with best-effort flush; fallback compare-and-put on `updatedAt` inside one transaction; `BroadcastChannel` `rgb-pencil-projects` for list changes and deletions.
  - Legacy adoption: read `rgb-pencil:v1:<hash>` once at project creation, drop out-of-range cells, remove the key; never write legacy keys.

## 4. Sequential Execution Loop (Execute for i = 1 .. 3)

For each change `<change-i>` in order `1 .. 3`:

1. **Pre-Flight Check**:
   - Confirm `git status` is clean (previous change was committed).
   - Check the **Cross-Change Isolation Matrix**: if any earlier change is `BLOCKED` or halted, **HALT** immediately and do NOT start `<change-i>` (all changes here are coupled).
   - For Changes 2 and 3, confirm the symbols they depend on exist from the prior change (`EngineClient`, `MatchedGrid`, `gridStore`; then `WorkingBitmap`, `sourceHash`, `PIPELINE_VERSION`). If missing, HALT.

2. **Delegate Implementation to `spec-coder-sub`**:
   - Instruct `spec-coder-sub` to implement `<change-i>` adhering strictly to its Target Context Map, Vertical Slice Architecture (VSA), the TDD Group 1 requirement (failing tests written and shown failing BEFORE implementation), real-time `tasks.md` checkbox updates, and population of `<changeDir>/verification.md` (Requirement Adherence Audit Matrix, resolved assumptions, nomenclature audit, verbatim logs).
   - Do NOT let `spec-coder-sub` create git commits, push, or switch branches; the orchestrator handles atomic commits after verification.

3. **Verify Implementation (`openspec-verify-change`)**:
   - Confirm all completed checkboxes in `<changeDir>/tasks.md` genuinely ran and passed.
   - Confirm `<changeDir>/verification.md` is populated.
   - Confirm that `npm test` and `npm run build` pass for the **whole repository** (not just this change's tests), so earlier changes did not regress.
   - Run **`openspec-verify-change`** for `<change-i>`.

4. **Single Bounded Repair Pass (Max Retries = 1)**:
   - **If CRITICAL issues or test failures are detected on the first verification pass**:
     1. Announce: `"Change '<change-i>' verification failed on initial pass. Attempting a single bounded repair pass via spec-coder-sub..."`
     2. Delegate **1** targeted repair task to `spec-coder-sub` with the verbatim verification failure log and instructions to make minimal targeted patches and re-run verification.
     3. Re-run **`openspec-verify-change`** for `<change-i>`.

5. **Gate, Atomic Commit, or Halt**:
   - **If verification passes with zero CRITICAL issues**:
     1. Sync delta specs via the `openspec-sync-specs` skill for `<change-i>`.
     2. Stage and commit `<change-i>` atomically on the batch branch:
        ```bash
        git add openspec/changes/<change-i> openspec/specs <implementation-files>
        git commit -m "feat(<change-i>): implement and verify change"
        ```
